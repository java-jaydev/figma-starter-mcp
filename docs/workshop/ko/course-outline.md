# 강의 진행안 (2시간, 개발자 대상)

목표: 수강생이 Figma 무료(Starter) 계정 하나로 라이트/다크 색 변수, 간격 변수, 텍스트 스타일, Section 구조를 갖춘 디자인 시스템 파일을 만들고, 그 과정을 플러그인 스크립트로 자동화할 수 있다.

준비물: Figma 데스크톱 앱, 무료 계정, 이 레포의 `docs/workshop/token-plugin/` 폴더, 코드 편집기.

## 1. 무료 플랜의 벽 한눈에 보기 (10분)

- 진행 노트: `../../../skills/figma-build/references/limits-and-sources.md` 의 표를 띄우고 "한도 - 우회법" 짝으로 훑는다. 이 강의는 실제로 Starter 계정으로 디자인 시스템을 만들며 부딪힌 순서를 따라간다고 소개한다.
- 강조: 숫자는 바뀐다. 표에 확인일과 출처가 있는 이유를 말한다.
- 예상 질문: "그냥 Professional 쓰면 되지 않나요?" - 개인 사이드 프로젝트, 학습, 소규모 팀 초기에는 무료로도 충분하고, 제약을 알면 나중에 옮길 때도 구조가 깔끔하다.

## 2. 페이지 대신 Section (20분)

- 진행 노트: Starter 디자인 파일은 페이지가 3개까지다. 디자인 시스템은 보통 Foundations, Components, Patterns, Playground 처럼 페이지를 많이 쓰는데, 이걸 한 페이지 안의 Section 으로 나눈다.
- 화면 시연: 도구 막대에서 Section 도구(단축키 Shift+S)로 Section 을 그리고 이름을 붙인다. 왼쪽 레이어 패널에서 Section 이 폴더처럼 접히는 것을 보여 준다.
- 남은 페이지 2개 쓰는 법 제안: 1페이지 = 시스템(Section 으로 구분), 2페이지 = 실험장, 3페이지 = 아카이브.
- 실습 1 진행 (`labs.md`).
- 예상 질문: "Section 안에 Section 도 되나요?" - 된다. 다만 깊게 중첩하면 찾기 어려우니 두 단계까지만 권한다.

## 3. 모드 대신 컬렉션 2개 (25분)

- 진행 노트: 변수 모드는 플랜별 한도가 있고, Starter 에서는 실제로 컬렉션당 모드 1개만 만들 수 있었다. 그래서 `Color / Light`, `Color / Dark` 두 컬렉션에 **같은 이름**의 변수를 만든다.
- 코드와 연결: 개발자에게는 CSS 의 `:root` 와 `[data-theme="dark"]` 에 같은 변수 이름을 두 번 정의하는 것과 같다고 설명한다.
- 단점도 솔직히: 모드 전환 한 번으로 화면 전체를 바꾸는 기능은 못 쓴다. 다크 화면은 다크 컬렉션 변수를 직접 바인딩해서 따로 만든다. 나중에 유료로 옮기면 두 컬렉션을 하나로 합치고 모드 2개로 바꾸면 된다.
- 실습 2 진행 (`labs.md`). 손으로 2개만 만들어 보고 "이걸 수십 개 하면?" 이라는 질문으로 다음 블록에 넘어간다.

## 4. 개발용 플러그인으로 자동화 (35분)

- 진행 노트: 개발용 플러그인은 데스크톱 앱에서 `manifest.json` 을 불러와 바로 실행한다. 공식 문서에 플랜 제한이나 호출 한도가 없어서, Starter 에서 반복 작업을 맡기기 좋다.
- 코드 읽기 (10분): `code.js` 를 같이 읽는다.
  - `TOKENS`: 데이터. 수강생이 고칠 곳은 여기뿐.
  - `getCollection`, `upsertVariable`: 같은 이름이 있으면 재사용해서 여러 번 실행해도 중복이 안 생긴다.
  - `buildTextStyles`: 글꼴을 `loadFontAsync` 로 먼저 불러와야 스타일에 지정할 수 있다.
  - `buildSections`: 블록 2 에서 손으로 한 일을 코드로.
  - `manifest.json` 의 `documentAccess: "dynamic-page"`: 그래서 `getLocal...Async` 같은 비동기 API 를 쓴다.
- 실습 3 진행 (20분).
- 마무리 (5분): 토큰을 JSON 으로 빼서 코드 저장소와 Figma 가 같은 값을 쓰게 하는 방향을 소개한다.

## 5. MCP 는 아껴 쓰기 (10분)

- 진행 노트: Figma MCP 서버는 AI 코딩 도구가 Figma 파일을 읽고 쓰게 해 준다. Starter 는 한 달 호출 수가 아주 적어서, 디자인 시스템을 MCP 로 만들다 보면 금방 막힌다(실제 경험).
- 공식 문서에 따르면 파일에 쓰는 일부 도구는 한도에서 빠진다. 한도를 깎는 건 주로 읽기 호출이다.
- 정리: 반복 생성은 플러그인, MCP 는 "완성된 화면을 코드로 옮길 때" 같은 꼭 필요한 순간에만.
- 예상 질문: "한도가 언제 초기화되나요?" - 월 단위다. 정확한 기준은 공식 FAQ 를 같이 열어 확인한다.

## 6. 글꼴, 라이브러리, 마무리 (10분)

- 글꼴: 새로 설치한 글꼴은 데스크톱 앱을 다시 시작해야 보인다. 강의 전 준비물 안내에 넣는다.
- 라이브러리: Starter 는 팀 라이브러리로 공유하기 어렵다. 그래서 파일을 "토큰 파일, 컴포넌트 파일" 로 나누지 않고 한 파일에 모았다. 파일 수(3개) 한도와도 맞아떨어진다.
- Q&A.
