# 실제 Figma 확인 기록: v0.1.2 (2026-11-11)

[v0.1.1 확인 기록](2026-11-11-v1.md)의 남은 일 가운데 둘을 고치고 Figma 데스크톱 앱(macOS, Starter)에서 다시 확인했다. 쓰기 시험은 지난번과 같은 빈 시험 파일에서만 했다. 도구는 MCP SDK 클라이언트로 서버를 직접 띄워 불렀다.

## 결과 요약

| 항목 | 결과 |
|---|---|
| 글자 레이어가 없는 컴포넌트에 TEXT 속성 추가 | 통과. `INVALID_INPUT`, 힌트 "Add the text first with create_text" |
| 글자 레이어가 하나일 때 TEXT 속성 추가 | 통과. 그 레이어에 자동으로 이어지고 `linkedLayerId` 를 돌려줌 |
| 글자 레이어가 둘일 때 `layerId` 없이 TEXT 속성 추가 | 통과. 오류 힌트에 후보 `5:4 (Tag), 5:5 (Note)`, 속성은 생기지 않음 |
| 같은 경우 `layerId` 를 넘겨 추가 | 통과 |
| 인스턴스에서 `set_instance_properties` 로 TEXT 값 바꾸기 | 통과. 화면 글자가 `Done`, `Saved` 로 바뀜 (v0.1.1 에서 안 되던 것) |
| BOOLEAN 속성을 글자 레이어 보이기에 잇고 인스턴스에서 끄기 | 통과. PNG 내보내기에서 해당 글자가 사라짐 |
| INSTANCE_SWAP 속성에 TEXT 레이어를 넘기기 | 통과. `INVALID_INPUT` 으로 거절 |
| INSTANCE_SWAP 속성을 안쪽 인스턴스에 잇기 | 통과 |
| `read_page` 기본값 | 통과. 깊이 2 에서 멈추고 더 깊은 노드는 `omitted` 수로 표시. 시험 파일에서 2,706자 (깊이 4 로 읽으면 9,469자) |

## v0.1.2 에서 바뀐 것

1. `add_component_property` 가 속성을 컴포넌트 안 레이어에 잇는다. TEXT 는 글자, BOOLEAN 은 보이기, INSTANCE_SWAP 은 바꿀 인스턴스. `layerId` 인자를 받고, TEXT 는 글자 레이어가 하나면 자동으로 잇는다. 잘못된 `layerId` 는 속성을 만들기 전에 거절한다.
2. `read_page` 와 `read_nodes` 가 `maxDepth`, `maxNodes` 를 받는다. `read_page` 의 기본 깊이는 4 에서 2 로 줄었다. 큰 컴포넌트 페이지 하나가 146,033자로 MCP 응답 한도를 넘었던 것이 이유다.

## 남은 일

- 연결이 열린 뒤 인증 단계에서 실패하면 UI 가 "Server not running" 만 보여 원인이 가려진다.
- 컴포넌트 삭제 확인창에 다른 곳에서 쓰는 인스턴스 수를 보여 주기.
- 확인창 문구 `1 nodes` 의 단수형.
- Windows, Linux, Claude Code 플러그인 마켓플레이스, Codex, Gemini CLI, Grok Build 는 확인하지 않았다. 사용자 제보는 이슈 양식으로 받는다.
