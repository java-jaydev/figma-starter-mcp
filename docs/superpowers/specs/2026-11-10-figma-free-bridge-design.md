# Figma 무료 플랜용 AI 브리지 설계

작성일: 2026-11-10
상태: 검토 대기 (빌더 점검 반영)

표기: **[결정]** 은 사용자가 정한 것, **[판단]** 은 작성자(에이전트)가 정한 기본값이다. [판단] 은 사용자가 바꿀 수 있다.

## 1. 의도와 이유

개발자의 경쟁력이 코드만으로는 부족해지고 있다. 개발자도 기획, 디자인, 설계를 직접 해야 한다. 그래서 개발자가 Figma 에서 화면을 직접 만들고, 그 화면을 다시 코드로 옮기는 흐름이 필요하다. **[결정]**

이 흐름을 AI 코딩 도구(Claude Code, Codex, Gemini CLI, Grok Build)로 하려면 Figma 와 AI 도구를 잇는 연결이 있어야 한다. 그런데 무료(Starter) 계정에서는 공식 연결 수단이 사실상 막혀 있다.

- 공식 Figma MCP 서버: Starter 는 월 최대 20회. ([Rate limits & access](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/))
- Figma REST API: 2025-11-17 부터 파일, 노드, 이미지 읽기가 무료 좌석에서 월 최대 20회. REST 기반 도구(Framelink 등)도 사실상 못 쓴다. ([REST API rate limits](https://developers.figma.com/docs/rest-api/rate-limits/))
- 공식 MCP 의 캔버스 쓰기(`use_figma`)는 베타라 지금은 무료지만, 사용량 기반 유료로 바뀐다고 공지돼 있다. ([Figma MCP server FAQs](https://help.figma.com/hc/en-us/articles/39252411778583))

반면 Figma 데스크톱 앱의 개발용 플러그인은 Plugin API 를 로컬에서 직접 부르므로 REST 한도와 무관하다. 이 경로로 무료 계정 개발자도 AI 도구를 Figma 에 연결해 쓸 수 있게 한다. **[결정]**

차별점은 연결 자체가 아니라 **개발자가 만들면 Figma 파일이 처음부터 개발 친화적으로 만들어진다**는 데 있다. **[결정]** 연결 계층은 기존 공개 프로젝트의 기능을 참고해 클린룸으로 직접 구현하고, 그 위에 작업 방식을 스킬과 규칙으로 얹는다. **[결정]**

## 2. 쓰는 사람과 장면

- 디자이너 없이 직접 화면을 그리는 개발자. Figma 무료 계정, 데스크톱 앱.
- 장면 A (화면 만들기): "이 기능의 설정 화면을 Figma 에 그려 줘" 라고 하면, AI 가 기존 변수와 컴포넌트를 먼저 확인하고, 없으면 토큰부터 만들고, 오토 레이아웃으로 화면을 짠 뒤, 규칙 검사를 통과한 결과를 보여 준다.
- 장면 B (코드로 옮기기): "선택한 프레임을 React 로 옮겨 줘" 라고 하면, AI 가 프레임의 구조, 변수 바인딩, 컴포넌트 속성을 읽어 프로젝트의 기존 토큰과 컴포넌트에 맞춰 코드를 쓴다.
- 장면 C (시스템 세우기): 새 프로젝트에서 "디자인 시스템 기초를 깔아 줘" 라고 하면 색/간격/글꼴 변수, 텍스트 스타일, 구역(Section)이 무료 플랜 제약에 맞게 만들어진다.

## 3. 목표, 비목표, 안티목표

### 목표

1. 무료 Figma 계정 + 데스크톱 앱만으로, Figma 토큰이나 REST 호출 없이 AI 도구가 Figma 를 읽고 쓸 수 있다.
2. AI 가 만든 Figma 파일이 개발 친화 규칙(6장)을 지킨다. 규칙 위반은 도구가 찾아서 알려 준다.
3. Figma 에서 코드로 옮길 때 같은 규칙을 거꾸로 써서, 번역 없이 토큰 이름과 컴포넌트 속성이 그대로 코드에 이어진다.
4. Claude Code, Codex, Gemini CLI, Grok Build 에서 각각 짧은 설치 절차로 쓸 수 있다.
5. 문서는 한국어 기본, 영어/일본어/중국어(간체) 지원. **[결정, 이전 대화]** v1 범위 **[판단]**: README 와 docs 는 4개 언어. 스킬과 규칙 참고 문서는 AI 가 읽는 문서라 하나의 원본(한국어)만 두고, AI 는 사용자 언어로 답한다. 플러그인 UI 와 오류 메시지는 v1 에서 영어만.

### 비목표

- 디자이너용 범용 Figma 자동화 도구. 대상은 개발자다.
- 공식 Figma MCP 의 기능을 모두 따라잡기. 필요한 기능만.
- 코드 생성 엔진. 코드는 AI 도구가 쓴다. 브리지는 정확한 구조 정보를 넘기는 데 집중한다. **[판단]**
- FigJam, Figma Slides, Figma Sites 지원. **[판단]**
- 원격(클라우드) 연결. 같은 컴퓨터 안에서만 동작한다. **[판단]**

### 안티목표 (기술적으로 돌아가도 실패인 것)

- 기존 프로젝트의 소스 코드를 보거나 옮긴 흔적이 있다. (클린룸 위반)
- 설치나 사용 중 어디선가 Figma 개인 토큰을 요구하거나, Figma REST API 를 부른다.
- 같은 컴퓨터의 다른 프로그램이 인증 없이 소켓에 붙어 Figma 파일을 고칠 수 있다.
- AI 가 만든 화면이 하드코딩 색과 절대 좌표로 가득해서, 사람이 손으로 다시 정리해야 한다.
- 사용자 동의 없이 노드를 대량 삭제한다.

## 4. 제약

- **클린룸** **[결정]**: 기존 프로젝트(Figma Console MCP, Figwright, Talk to Figma MCP, Framelink 등)는 공개 README 와 기능 목록 수준으로만 참고한다. 소스 코드 파일은 열지 않는다. 구현 근거는 Figma 공식 Plugin API 문서, 공식 manifest 문서, MCP 공식 명세와 공식 SDK 문서뿐이다. 구현을 맡는 사람이나 에이전트 모두에게 적용한다. 지금까지 참고한 범위는 `docs/research/prior-art.md`(이 문서와 함께 커밋할 조사 노트)에 남긴다.
- **무료**: 사용자가 돈을 낼 일이 없어야 한다. 외부 유료 서비스에 의존하지 않는다.
- **로컬 전용**: 서버는 `127.0.0.1` 에만 바인딩한다. 플러그인 manifest 의 `networkAccess` 에 localhost 를 이유(`reasoning`)와 함께 적는다. ([Plugin manifest](https://developers.figma.com/docs/plugins/manifest/), [Making network requests](https://developers.figma.com/docs/plugins/making-network-requests/))
- **Figma Starter 제약을 전제로**: 파일 3개, 파일당 페이지 3개, 변수 컬렉션당 모드 1개(실측), 팀 라이브러리 없음. 규칙과 도구가 이 제약 안에서 동작해야 한다. 유료 계정에서는 모드를 쓰는 쪽으로 자연스럽게 넘어갈 수 있게 한다.
- **레포 규칙**: em dash, en dash 금지(하이픈만). 개인 정보(이메일, 계정)를 자료와 외부 요청에 넣지 않는다. main 직접 커밋 금지.

## 5. 구조

```text
AI 도구 (Claude Code / Codex / Gemini CLI / Grok)
   │  MCP (stdio)
   ▼
브리지 서버 (Node, npx 로 실행)  ── 127.0.0.1 WebSocket + 짝 맺기 코드 ──▶  Figma 개발용 플러그인
   │                                                                     │
   └ 규칙 검사기(lint), 결과 요약                                          └ Plugin API 실행
스킬 (작업 순서와 규칙) ── AI 도구가 읽음
```

### 5.1 브리지 서버 **[판단: TypeScript, Node, npm 패키지로 배포해 `npx` 로 실행]**

- AI 도구와는 MCP stdio 로 말한다. 공식 MCP TypeScript SDK 를 쓴다.
- 플러그인과는 `127.0.0.1` WebSocket 으로 말한다. 포트는 고정 기본값 하나를 쓴다(아래 동시 실행 참고).
- **짝 맺기** **[판단]**: 서버가 시작할 때 짧은 코드를 만들어 AI 도구 쪽 출력(또는 상태 도구 결과)에 보여 준다. 사용자가 플러그인 창에 그 코드를 넣어야 연결된다. 연결 뒤에는 세션 토큰으로 메시지를 인증한다. 한 번에 한 플러그인만 연결한다.
- **여러 AI 세션 동시 실행** **[판단]**: AI 도구 세션마다 stdio 서버가 하나씩 뜬다. 고정 포트를 먼저 잡은 프로세스가 허브가 되어 플러그인과 연결하고, 나중에 뜬 서버는 같은 포트의 허브에 클라이언트로 붙어 요청을 넘긴다. 허브가 꺼지면 남은 서버 중 하나가 허브를 이어받는다. 그래서 manifest 에는 고정 포트 하나만 적는다.
- **짝 맺기 기억** **[판단]**: 처음 짝을 맺으면 비밀 값을 사용자 설정 폴더(서버)와 플러그인 `clientStorage`(플러그인)에 저장해, AI 세션을 다시 켜도 코드를 다시 넣지 않는다. 플러그인 창에서 짝 풀기를 할 수 있다.
- 요청마다 타임아웃과 명확한 오류 메시지(플러그인 미연결, 파일 미열림, 글꼴 없음 등)를 준다.
- 대량 쓰기는 한 번의 왕복으로 묶는 배치 도구를 둔다.

### 5.2 Figma 개발용 플러그인 **[판단: TypeScript, 빌드 결과를 패키지에 포함]**

- 데스크톱 앱에서 Import plugin from manifest 로 불러온다. 지금은 Figma Community 게시 없이 사이드로드한다. 게시는 나중 결정이다.
- 작은 UI 창: 연결 상태, 짝 맺기 코드 입력, 최근 작업 기록, 위험 작업 확인 버튼.
- `documentAccess: "dynamic-page"` 를 쓰고 비동기 API 를 쓴다.
- 기존 실습 플러그인(`assets/token-plugin/code.js`)의 변수, 텍스트 스타일, Section 생성 로직은 이 플러그인의 명령으로 흡수한다(작성자 본인 코드라 클린룸 대상 아님).

### 5.3 MCP 도구 범위 (v1) **[판단]**

| 묶음 | 도구 예시 | 비고 |
|---|---|---|
| 연결 | 상태 확인, 짝 맺기 안내 | |
| 읽기 | 현재 파일/페이지/선택 정보, 노드 트리(코드 친화 요약), 변수 컬렉션과 변수, 텍스트 스타일, 로컬 컴포넌트와 속성, 노드 PNG/SVG 내보내기 | 장면 B 의 핵심. 요약 형식은 7장 |
| 토큰 쓰기 | 컬렉션/변수 만들기와 고치기, 텍스트 스타일 만들기, 변수 바인딩 | Starter 에서는 라이트/다크를 컬렉션 2개로 (6장) |
| 구조 쓰기 | Section, 오토 레이아웃 프레임, 텍스트, 사각형, 컴포넌트 만들기, 컴포넌트 속성, 인스턴스 배치, 속성 덮어쓰기 | |
| 편집 | 이름 바꾸기, 이동, 크기, 오토 레이아웃 설정, 삭제 | 확인 범위는 아래 |
| 검사 | 규칙 검사(lint): 하드코딩 색/간격, 오토 레이아웃 누락, 이름 규칙 위반, 바인딩 안 된 텍스트 스타일 | 결과는 노드 ID 와 고칠 방법 |
| 배치 | 여러 쓰기 명령을 한 번에 | |

- **사용자 확인이 필요한 작업** **[판단]**: 한 번에 노드 5개 이상 삭제, 컴포넌트/변수/컬렉션/스타일 삭제. 배치 안에 이런 작업이 있으면 배치 전체를 실행 전에 한 번 확인받는다. 확인 대기는 일반 타임아웃과 별도(기본 2분)이고, 거절이나 시간 초과는 아무것도 바꾸지 않은 채 오류로 돌려준다. 레이어 4개 이하 삭제와 값 덮어쓰기는 확인 없이 실행하되 Figma 실행 취소(undo)로 되돌릴 수 있게 한 묶음으로 커밋한다.
- **규칙 강제** **[결정: 기본 막기, 명시하면 허용]**: 쓰기 도구는 색, 간격, 모서리, 글꼴 크기를 변수/스타일 이름으로 받는다. 프레임은 기본이 오토 레이아웃이다. 원시 값(예: `#4F46E5`)이나 오토 레이아웃 없는 프레임은 AI 가 요청에 규칙 예외 표시와 이유를 함께 넣어야 실행되고, 그 이유는 노드에 기록되어(plugin data) 규칙 검사 결과에 계속 예외로 표시된다. 검사기는 플러그인 쪽에서 노드를 직접 보고 판단한다 [판단].
- 임의 Plugin API 코드를 실행하는 도구는 v1 에서 **넣지 않는다** **[판단]**. 강력하지만 규칙을 우회하고 보안 위험이 크다. 필요해지면 기본 꺼짐 옵션으로 검토한다.

### 5.4 스킬과 규칙 **[결정: 스킬과 규칙을 얹는다 / 판단: 구성]**

- 스킬 2개 **[판단]**:
  - 만들기 스킬: 장면 A, C. 순서 = 연결 확인, 기존 토큰/컴포넌트 읽기, 없으면 토큰부터, 오토 레이아웃으로 구성, 규칙 검사, 결과 스크린샷으로 확인.
  - 옮기기 스킬: 장면 B. 순서 = 선택 노드 읽기, 프로젝트 코드의 토큰/컴포넌트와 대응표 만들기, 코드 작성, 대응 안 되는 것 보고.
- 규칙 본문(6장)은 스킬의 참고 문서 한 곳에만 둔다. 검사기 구현은 같은 규칙을 코드로 옮긴 것이다.
- 무료 플랜 한도 표와 출처(기존 `limits-and-sources.md`)는 스킬 참고 문서로 유지하고 확인일을 관리한다.

## 6. 개발 친화 규칙 (v1 초안) **[판단: 사용자 검토 필요]**

1. **값은 변수로**: 색, 간격, 모서리, 글꼴 크기는 변수 또는 텍스트 스타일에 바인딩한다. 하드코딩 금지.
2. **토큰 이름 = 코드 이름**: `color/bg/default` 처럼 슬래시 경로. 코드에서는 `--color-bg-default`, `tokens.color.bg.default` 로 기계적으로 바뀐다.
3. **테마**: 유료 플랜이면 컬렉션 하나에 모드 2개. Starter 면 `Color / Light`, `Color / Dark` 컬렉션 2개에 같은 이름 변수. 옮기기 스킬은 두 형태를 모두 읽는다.
4. **레이아웃 = flex**: 화면과 컴포넌트의 프레임은 오토 레이아웃. 절대 위치는 장식 요소만 허용하고 이름에 표시한다.
5. **컴포넌트 = 코드 컴포넌트**: 컴포넌트 이름은 PascalCase(`Button`), 속성 이름은 camelCase props(`variant`, `size`, `disabled`). 변형 값은 코드의 유니언 값과 같게.
6. **레이어 이름**: 의미 있는 이름(`header`, `actions`). `Frame 12` 같은 기본 이름은 검사에서 경고.
7. **파일 구조**: Starter 페이지 3개 안에서 1페이지 = 시스템(Section: Foundations, Components, Patterns), 2페이지 = 화면, 3페이지 = 실험장.

## 7. 코드 친화 요약 형식 **[판단: 형식 세부는 빌더 몫]**

읽기 도구는 Figma 노드를 그대로 덤프하지 않고 코드로 옮기기 좋은 요약을 준다: 노드 종류, 이름, 오토 레이아웃(방향, 간격, 패딩, 정렬, 크기 규칙), 바인딩된 변수 이름(값이 아니라 이름 우선), 텍스트 스타일 이름, 컴포넌트 인스턴스의 컴포넌트 이름과 속성 값, 규칙 위반 표시. 토큰 수를 아끼기 위해 깊이와 필드를 조절하는 옵션을 둔다.

## 8. 설치와 배포 **[판단]**

- npm 패키지 하나에 서버와 플러그인 빌드 결과를 담는다. 플러그인 폴더 위치를 알려 주는 명령을 둔다.
- Claude Code: 플러그인(마켓플레이스)에 MCP 서버 설정과 스킬 포함.

- Codex: MCP 서버 등록 방법과 스킬 복사 방법을 문서로. Grok Build 도 같은 방식(스킬은 `~/.agents/skills/` 또는 Claude 스킬 자동 인식).
- 각 도구의 실제 설정 형식은 구현 시점에 각 공식 문서로 확인한다.
- **v1 완료 기준** **[판단]**: GitHub 에서 바로 설치(`npx github:<레포>` 형태)되고, Claude 마켓플레이스와 Gemini 확장이 새 구성으로 갱신되고, Claude Code 와 Gemini CLI 에서 실제 설치를 확인. Codex 와 Grok 은 설치 문서까지. npm 게시는 패키지 이름이 정해진 뒤 별도 단계(npm 계정이 필요하므로 그때 사용자 확인).

## 10. 기존 자산

- 4개 언어 강의 자료(강사 진행안, 실습)는 `docs/workshop/` 으로 옮겨 "이 도구로 하는 2시간 워크숍" 문서로 남긴다 **[판단]**. 스킬에서는 뺀다.
- 무료 플랜 한도 표는 스킬 참고 문서로 유지(5.4).
- 토큰 생성 플러그인 로직은 새 플러그인 명령으로 흡수(5.2). 기존 테스트 방식(가짜 figma 객체로 실행)은 플러그인 명령 테스트의 출발점.

## 11. 검증

- 플러그인 명령: 가짜 `figma` 객체로 단위 테스트(기존 방식 확장). 멱등성과 Starter 제약(모드 1개) 포함.
- 서버: MCP 도구 입력 검증, 짝 맺기와 인증 거부, 타임아웃을 테스트.
- 규칙 검사기: 위반/통과 예제 노드로 테스트.
- 실제 Figma 데스크톱 앱에서의 확인은 체크리스트로(장면 A, B, C 각 1회). 자동화하지 않는다.
- 보안 확인: 다른 출처의 소켓 연결, 잘못된 코드, 세션 토큰 없는 메시지가 모두 거부되는지.

## 12. 빌더에게 맡기는 것

- 포트 번호, 메시지 형식(JSON 등), 재연결 정책.
- 도구의 정확한 이름과 입력 스키마(5.3 범위 안에서).
- 플러그인 UI 모양.
- 요약 형식의 세부 필드(7장 원칙 안에서).
- 빌드 도구, 테스트 프레임워크, 모노레포 여부.

## 13. 열린 질문

- Figma 개발자 약관과 플러그인 가이드라인이 이런 로컬 브리지를 제한하는지 직접 확인 필요(조사 때 미확인). 선례로 Talk to Figma 플러그인이 Figma Community 에 게시돼 있다. **[판단]** 구현 계획의 첫 작업으로 확인하고, 제한이 있으면 구현 전에 멈추고 사용자에게 알린다.
- 공식 `use_figma` 가 Starter 한도에서 계속 빠지고 무료로 남으면 쓰기 쪽 가치는 줄어든다. 읽기는 여전히 한도에 걸리므로 핵심 가치는 유지된다.
